# گزارش بررسی و اصلاح کیاراد بی‌آی

تاریخ: ۷ نوامبر ۲۰۲۶. مبنا: ZIP ارسالی همین گفتگو.

**نتیجه: بستهٔ اصلاحات آمادهٔ اعمال و بازبینی است؛ مهاجرت تولید و تست تمام سناریوهای کاربری تأیید نشده است.** هیچ تغییری روی `D:\project\kiaradbi` یا سرویس‌های واقعی انجام نشده است.

## اصلاحات

| حوزه | مشکل مشاهده‌شده | اصلاح |
|---|---|---|
| دیتابیس | ساخت URL با الحاق رشته، خرابی با رمزهای دارای @ و / | استفاده از SQLAlchemy URL.create |
| اسکریپت‌های فعال | مسیر ثابت D و اتصال مستقل با رمز ثابت | چهار اسکریپت از مسیر فایل و تنظیمات مشترک استفاده می‌کنند |
| کاتالوگ استاتیک | خطر خواندن JSON نیمه‌نوشته هنگام بازسازی | انتشار با فایل موقت یکتا و replace |
| وابستگی بک‌اند | import مستقیم dotenv بدون ذکر صریح در requirements | افزودن python-dotenv پین‌شده |
| CORS | دو middleware با wildcard و credentials | یک middleware و KIARAD_CORS_ORIGINS؛ پیش‌فرض فقط localhost:3000 و 127.0.0.1:3000 |
| احراز هویت | dependency کارمندی توکن مشتری را مستقل رد نمی‌کرد | رد صریح site_customer پیش از دسترسی به users |
| دروازه API | پذیرش خانوادهٔ سفارش مشتری با startsWith | فقط /site-orders و /site-orders/mine؛ بنر عمومی فقط خواندنی |
| مشتری سایت | sub خراب می‌توانست 500 بدهد | شناسهٔ مثبت و خطای 401 برای شناسه نامعتبر |
| ورود سایت | CREATE TABLE داخل connect بدون commit | engine.begin برای مقداردهی پایدار |
| سفارش سایت | ردیف‌های تکراری کنترل موجودی را جداگانه دور می‌زدند | جمع تعداد هر کد پیش از کنترل و محاسبهٔ قیمت سرور؛ آماده‌سازی جدول CMS در همان تراکنش |
| سفارش سکوها | لغو بدون push، فعال‌سازی مجدد بدون فعال‌کردن رزرو، باقی‌ماندن ردیف حذف‌شده | reconcile snapshot کامل، جمع ردیف تکراری، آزادسازی/فعال‌سازی و push پس از commit |
| فرانت | ۷ خطای lint و وابستگی ناقص effect | انتقال reset به رویداد، بارگذاری async، نوع‌دهی reconciliation و تثبیت callback ورود |
| Docker فرانت | npm install بدون تکیه بر lockfile | npm ci با package-lock.json |
| Docker بک‌اند | secrets خارج image ولی بدون mount؛ خروجی CMS ناپایدار | mount secrets به‌صورت قابل‌نوشتن برای refresh، مدل گفتار فقط‌خواندنی و site پایدار؛ مدل‌ها از image حذف شدند |
| اتصال هلو | import با HOLO_API_URL خالی کرش می‌کرد | import امن؛ خطای صریح هنگام درخواست login بدون پیکربندی |
| سرور فروشگاه | decodeURIComponent نامعتبر کل سرور را می‌بست | پاسخ 400، کنترل متد/HEAD، timeout پراکسی و پشتیبانی upstream HTTPS |

رزرو سکوها اکنون ورودی `items` را snapshot کامل سفارش می‌داند. مصرف‌کننده‌ای که فقط تغییر یک ردیف را می‌فرستد باید پیش از فراخوانی snapshot کامل بسازد. آزمون‌های این منطق با DB mock بوده‌اند؛ تراکنش واقعی روی PostgreSQL هنوز باید بررسی شود.

## شواهد اجرا

| بررسی | نتیجه | محدوده |
|---|---|---|
| زیرمجموعه آفلاین Python | 677 مورد انتخاب‌شده؛ 503 پاس، 174 skip، صفر خطا | 15 مورد وابسته به محیط/SQL صریحاً excluded؛ جزئیات در offline-tests.log |
| رگرسیون‌های جدید | 13 پاس | توکن، CORS، DB URL، سبد تکراری و رزرو سکوها؛ DB mock |
| مجموعهٔ کامل | 680 مورد شمارش‌شده، 174 skip، 10 گزارش error | پنج subtest دستیار، سه setUpClass محیط زنده، SQL مفقود و lookup مالی؛ نتیجهٔ کامل سبز نیست |
| TypeScript | پاس | بررسی مستقل و مرحلهٔ build |
| lint | صفر خطا، 2 هشدار | دو img در CMS |
| build production | پاس، 46 صفحه تولید شد | Node 24.22.1؛ workaround موقت برای متریک حافظهٔ sandbox؛ بدون تغییر محصول |
| HTTP صفحات پنل | 15 از 15 پاسخ 200 | صرفاً HTML؛ احراز هویت و داده در مرورگر تأیید نشده |
| HTTP فروشگاه | 7 سناریو پاس | URL خراب، بقا پس از درخواست خراب، HEAD، متد نامجاز، 404، proxy با upstream ساختگی |
| مرورگر/کلیک | اجرا نشد | Chromium هنگام launch با SIGSEGV بسته شد |
| نحو Python | 116 ماژول ریشه parse شد | جایگزین اجرای واقعی نیست |
| Docker و restore | اجرا نشد | Docker و PostgreSQL در محیط موجود نیست |

نصب Python برای تست‌ها با نسخه‌های پین‌شدهٔ fastapi، sqlalchemy، psycopg2، JWT، requests، uvicorn، jdatetime و multipart انجام شد. همهٔ requirements از جمله faster-whisper و نسخهٔ دقیق pandas نصب و تست نشدند؛ سازگاری کامل تصویر Docker از این نتایج نتیجه نمی‌شود. Starlette و Pydantic وابستگی‌های غیرپین‌شده هستند؛ برای انتشار قابل‌تکرار باید محیط نهایی نیز ثبت/قفل شود.

## موارد لازم پیش از شروع استفاده

1. فایل‌های اصلی `migrations/*.sql` را از پروژهٔ ویندوز حفظ کنید. در ZIP ارسالی به‌علت فیلتر اشتباه SQL موجود نیستند. baseline جدید نسازید و تست migration را حذف نکنید.
2. اصلاحات را با Apply-Review.ps1 روی پروژه اعمال کنید؛ این ابزار پیش از تغییر، هش سورس مبنا را کنترل و نسخهٔ پشتیبان می‌گیرد. اختلاف هش را با Force دور نزنید؛ فایل متفاوت باید merge شود.
3. فایل `.env` و secrets را روی سرور امن تنظیم کنید. برای دامنهٔ جدا، KIARAD_CORS_ORIGINS را با origin دقیق و بدون wildcard تنظیم کنید. توکن‌های دیجی‌کالا در ZIP ورودی موجود بودند؛ در خروجی نیستند و تعویض آن‌ها پیش از انتشار بیرونی توصیه می‌شود.
4. روی کپی آزمایشی دیتابیس و با اتصال‌های خارجی غیرفعال، requirements و npm ci نصب، build بدون workaround، تست کامل و گروه‌های دیتابیس مطابق run_full_test_suite.ps1 اجرا شود. نتایج تولیدی را با نتایج این محیط جایگزین نکنید.
5. بکاپ تازه و رسانه‌ها را جدا منتقل، checksum را کنترل و restore را روی دیتابیس خالی آزمایشی تمرین کنید. ZIP اصلاحات شامل دیتابیس، migration SQL اصلی، مدل گفتار یا رسانه‌ها نیست و بستهٔ مهاجرت مستقل نیست.
6. کلیک واقعی desktop/mobile با حساب‌های مدیرعامل، مالی، مدیر فروش و ویزیتور: ورود/خروج، تغییر رمز و انقضای نشست، محدودیت داده، جست‌وجو، ایجاد/ویرایش/لغو پیش‌فاکتور، اعتبار با تغییر سبد، تسک، برنامهٔ ماهانه/تأیید، GPS، دوربین/فایل، خزانه/حقوق، چاپ، CMS و سفارش سایت. ناموجودی، ورودی نامعتبر، قطع شبکه و دوبارکلیک نیز باید پوشش داده شوند.
7. هلو، AvalAI، دیجی‌کالا و تقویم تسک‌های Windows جدا بررسی شوند. Compose برای تسک‌های Windows جایگزین زمان‌بند نمی‌سازد؛ در صورت سرور Linux، معادل timer/cron لازم است. اتصال و نوشتن واقعی به سرویس بیرونی در این ممیزی انجام نشد.
8. فروشگاه عمومی هنوز رزرو اتمیک/کنترل مجموع سفارش‌های هم‌زمان در سایت ندارد؛ همین سفارش‌ها در create_order از platform_reservations استفاده نمی‌کنند. جلوگیری از بیش‌فروشی، تکرار checkout و ارسال دوباره درخواست تا تکمیل و تست این گردش کار تأیید نشده است. پیش‌فاکتور قبلیِ سفارش سکوها هم با تغییر snapshot بازنویسی نمی‌شود؛ همخوانی مبلغ و وضعیت آن نیاز آزمون مالی دارد. تا رفع این موارد سفارش عمومی فعال نشود.

## اجرای مجدد

از ریشهٔ پروژه، در محیط موجود پروژه:

```powershell
.\.venv\Scripts\python.exe scripts\run_offline_review_tests.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_release_regressions.py -v
node tests\node\storefront-http.test.mjs
.\scripts\run_full_test_suite.ps1
Set-Location kiarad-dashboard
npm ci
npx tsc --noEmit
npm run lint
npm run build
```

اسکریپت آفلاین، skipها و موارد excluded را گزارش می‌کند؛ موفقیت آن هرگز جایگزین تست کامل نیست. گزارش‌های خام در پوشهٔ evidence بسته قرار دارند.
