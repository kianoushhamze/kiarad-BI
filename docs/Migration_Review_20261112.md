# اصلاحات پیش از انتقال کیاراد BI

این نسخه بر پایهٔ main با شناسهٔ `09ebfd544e5fbd7b1bcdce4c569a05ab406077bb` است؛ تغییرات فروشگاه PR ۲ را حفظ می‌کند، اصلاحات اجرایی PR ۴ را در بر دارد و اصلاح سبد خرید PR ۳ را به فایل فعلی `site-healer/buy.html` منتقل می‌کند. PR ۳ مربوط به `site/index.html` حذف‌شده است؛ ادغام مستقیم آن جایگزین اصلاح مسیر فعلی نیست.

## تغییرات

- اولین ویرایش متادیتای محصول بدون hidden، مقدار پیش‌فرض معتبر می‌گیرد.
- حذف صریح تخفیف با null انجام می‌شود؛ نیاوردن فیلد تخفیف مقدار قبلی را حفظ می‌کند.
- پیام تغییر قیمت، تغییر در دیتابیس محلی کیاراد را گزارش می‌دهد و ادعای تغییر قیمت در هلو نمی‌کند.
- پاسخ خراب کاتالوگ، زنده تلقی نمی‌شود و سبد خرید را پاک نمی‌کند. در حالت کاتالوگ ذخیره‌شده نیز اقلام حفظ می‌شوند؛ نشان آفلاین پس از بازیابی اتصال پاک می‌شود.
- تست‌های دیتابیس از شمای مستقل و دادهٔ ساختگی استفاده می‌کنند. CI تست‌های PostgreSQL و Node را نیز اجرا می‌کند.

## اصلاح راهنمای انتقال قبلی

فایل `Kiarad-Transfer-20261113.md` به `a106bf7` اشاره دارد که تغییرات فروشگاه ادغام‌شده در main را ندارد. بستهٔ تازه را از commit دقیق همین اصلاحات، پس از تأیید CI، بسازید. بسته و دستور قدیمی، نسخهٔ تأییدشدهٔ این اصلاحات نیستند. SHA نصب را همراه بسته ثبت کنید.

داشبورد Docker روی پورت ۳۰۰۰ است. فروشگاه فعلی سرویس مستقل Node روی پورت ۸۰۹۰ است؛ `/buy/` روی این سرویس ارائه می‌شود. docker-compose فعلی فروشگاه را اجرا نمی‌کند. تغییر مقصد تونل داشبورد به ۳۰۰۰ به‌تنهایی فروشگاه را منتشر نمی‌کند.

پس از بازیابی دیتابیس و اجرای داشبورد، در پوشهٔ نسخهٔ جدید روی سرور و با Node.js 22 نصب‌شده، فروشگاه را اجرا کنید:

```powershell
$releaseRoot = (Get-Location).Path
$env:KIARAD_API_URL = 'http://127.0.0.1:8000'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-kiaradhealer-site.ps1 -SiteDir (Join-Path $releaseRoot 'site-healer') -ScriptDir (Join-Path $releaseRoot 'scripts') -Port 8090
```

این launcher پروسه‌های قبلی `serve_kiaradhealer.mjs` را متوقف می‌کند؛ آن را در مرحلهٔ تعویض نسخه اجرا کنید. پیش از انتشار، localhost:8090 و localhost:8090/buy/ و مسیر API کاتالوگ را بررسی کنید. برای دامنهٔ فروشگاه، مقصد تونل مستقل ۸۰۹۰ و برای دامنهٔ پنل مقصد ۳۰۰۰ لازم است. ثبت سفارش آزمایشی باید همان شمارهٔ رسید را در پنل نشان دهد.

ساخت بسته، بکاپ، توقف نوشتن در زمان انتقال و بازیابی خالی مطابق رویهٔ انتقال انجام شوند. برای build در پوشهٔ آرشیو، وجود `.env` مورد نیاز compose را با `docker compose config --quiet` بررسی کنید؛ `--env-file` جایگزین مسیر سرویس `env_file: .env` نیست. تنظیمات محرمانه را وارد Git یا بستهٔ عمومی نکنید.

## محدودهٔ تأیید

آزمون‌های این تغییر روی محیط آزمایشی مستقل انجام می‌شوند. ویندوز شرکت، Cloudflare، دیتابیس واقعی، منبع مالی هلو و دیجی‌کالا همچنان به پذیرش روی سرور شرکت نیاز دارند. sync خودکار را تا تعیین تنها سرور فعال روشن نکنید؛ در صورت ثبت دادهٔ واقعی روی مقصد، بازگشت بدون حفظ آن داده‌ها مجاز نیست.

## نکات تکمیلی بازبینی

- تغییر قیمت CMS فقط کاتالوگ محلی را تغییر می‌دهد. همگام‌سازی بعدی هلو ممکن است آن را بازنویسی کند؛ پیام پنل نیز باید همین محدوده را گزارش کند.
- خطای نبود `.env` با `docker compose config --quiet` در محیط آزمایشی بازتولید شد. این بررسی شکست خود فرمان `compose build` را اثبات نمی‌کند. برای اجرای Compose از سورس استخراج‌شده، فایل محیطی را امن کنار Compose قرار دهید؛ آن را به آرشیو سورس اضافه نکنید. `.dockerignore` فعلی فایل‌های `.env` را از ایمیج حذف می‌کند.
- اجرای پایدار فروشگاه و شروع خودکار آن پس از راه‌اندازی مجدد ویندوز باید با روش عملیاتی شرکت تنظیم و آزمایش شود. سالم بودن پنل روی پورت ۳۰۰۰، فعال بودن فروشگاه روی ۸۰۹۰ را ثابت نمی‌کند.
- آزمون کاتالوگ، حفظ سبد و کاتالوگ قبلی هنگام قطع شبکه و پاک‌شدن پیام خطا پس از بازیابی اتصال را نیز بررسی می‌کند.
