# تحویل کیاراد بی‌آی — ۸ نوامبر ۲۰۲۶

**وضعیت: سورس اصلاح‌شده و تست‌های قابل اجرا تحویل شده؛ بهره‌برداری روی سرور هنوز نیازمند اعتبارسنجی مقصد است.**

## مبنا و تغییرات

بستهٔ ورودی `kiaradbi-source-20261108-100152.zip` است. هیچ دسترسی اجرایی به `D:\project\kiaradbi`، دیتابیس کارفرما یا سرور مقصد در این جلسه وجود نداشت. این بسته به‌تنهایی برنامهٔ در حال اجرای ویندوز را تغییر نمی‌دهد.

۱. `kiarad-dashboard/app/login/page.tsx`: ورود روی HTTP به نام داخلی Docker وابسته بود؛ مسیر مشترک `API_URL` مرورگر (`origin + /api`) جایگزین شد. روی HTTPS هم همان مسیر واحد استفاده می‌شود.
۲. `config.py`: parser دستی `.env` کوتیشن و کامنت را جزئی از رمز می‌خواند؛ `dotenv_values` با UTF-8 BOM-tolerant جایگزین شد. متغیر محیطی همچنان اولویت دارد.
۳. `api.py`: پاسخ عمومی خطای اتصال دیتابیس شامل متن driver بود؛ اکنون پاسخ عمومی ثابت با کد 503 است.
۴. شش تست رگرسیون بک‌اند و چهار سناریوی ارسال فرم ورود اضافه شد؛ هنداف و راهنمای استقرار به‌روز شد.

## اعمال روی سیستم فعلی

۱. ZIP تحویل را در پوشه‌ای جدا استخراج کنید؛ کل پوشهٔ سورس را روی پروژهٔ زنده overwrite نکنید.
۲. `Apply-Update.cmd` را اجرا کنید؛ مسیر پیش‌فرض پروژه `D:\project\kiaradbi` است. ابزار ابتدا تمام هش‌های فایل‌های در حال تغییر را با بستهٔ ورودی تطبیق می‌دهد، سپس نسخهٔ فعلی همان فایل‌ها را در `_kiarad_backups` نگه می‌دارد و فقط فایل‌های فهرست‌شده در `update-manifest.json` را کپی می‌کند. اگر سورس پس از ارسال عوض شده باشد، اعمال متوقف می‌شود و merge لازم است.
۳. این ابزار `.env`، secrets، دیتابیس، داده، رسانه و سایر سورس‌ها را تغییر نمی‌دهد؛ سرویس را هم build/restart نمی‌کند. اسکریپت Windows در این محیط لینوکسی اجرا نشده و باید نتیجهٔ کنسول آن بررسی شود.
۴. پس از اعمال، تست‌ها را با دستورهای زیر روی سیستم خود اجرا کنید. نتیجهٔ دقیق را نگه دارید؛ ساخت ZIP یا پایان پنجره به معنی پاس‌شدن تست نیست.

```powershell
Set-Location D:\project\kiaradbi
& .\.venv\Scripts\python.exe scripts\run_offline_review_tests.py
& .\scripts\run_full_test_suite.ps1 -ProjectRoot D:\project\kiaradbi
node --test tests/node/*.test.mjs
Set-Location .\kiarad-dashboard
Get-ChildItem scripts\test-*.cjs | ForEach-Object { node $_.FullName; if ($LASTEXITCODE -ne 0) { throw $_.Name } }
npm run lint
npx tsc --noEmit
npm run build
```

هر فرمان در صورت کد خروج غیرصفر باید جداگانه بررسی شود. `run_full_test_suite.ps1` به محیط کامل و دیتابیس و API محلی نیاز دارد؛ گروه‌های opt-in دادهٔ آزمایشی می‌سازند. آمار اجرای قدیمی جای اجرای دوباره روی build نهایی را نمی‌گیرد.

## پیش از انتقال و شروع استفاده

- از دیتابیس و رسانه‌ها بکاپ تازه با checksum بگیرید. روی دیتابیس خالی آزمایشی restore و تعداد/مبالغ سفارش‌ها، مشتریان، موجودی، اسناد مالی و امکان ورود را تطبیق دهید. `0001_baseline.sql` جایگزین restore اسکیمای واقعی نیست.
- `.env`، پوشهٔ secrets، مدل صوت و رسانه‌های خصوصی جداگانه و امن منتقل شوند؛ در ZIP سورس نیستند. تایمرهای همگام‌سازی Windows روی مقصد خودبه‌خود ساخته نمی‌شوند؛ فهرست و تنظیمات آن‌ها را منتقل و هر نویسنده را فقط یک بار فعال کنید.
- طبق `docs/server-deployment.md`، build عادی روی مقصد، اجرای سرویس و سلامت backend/frontend بررسی شود. انتخاب روش Docker یا اجرای host باید مطابق runtime موجود باشد؛ هر دو را هم‌زمان روی یک پورت اجرا نکنید.
- پس از deploy، `node scripts/review_browser_local.mjs` را از ریشه و روی build تازه اجرا کنید؛ این ابزار فقط خواندنی است. سپس با دادهٔ آزمایشی گردش سفارش/لغو/عدم تکثیر، پیش‌فاکتور، خزانه، تأیید مدیر و محدودیت ویزیتور را بررسی کنید.
- GPS، دوربین، بارگذاری، صوت و چاپ روی دستگاه واقعی و در نشانی HTTPS مقصد آزمایش شوند. اتصال هلو، دیجی‌کالا و AvalAI و بازیابی پس از قطعی شبکه بررسی شود.
- پیش از جابه‌جایی کاربران، روش بازگشت به نسخهٔ قبل و بکاپ دیتابیس هماهنگ با آن آماده باشد؛ حجم postgres را حذف نکنید.

این موارد به دسترسی مقصد وابسته‌اند و در این جلسه انجام نشده‌اند. **هیچ داده یا سند مالی واقعی حذف، ادغام، ثبت یا اصلاح نشده است.**
