# راهنمای استقرار سرور کیاراد

این راهنما برای سرور ویندوزی شرکت نوشته شده است. رمزها داخل گیت، سند یا گفتگو قرار نمی‌گیرند.

## فایل‌های آماده

- `deploy.ps1`: ساخت، پشتیبان، مایگریشن، راه‌اندازی و کنترل سلامت.
- `scripts/backup_release.ps1`: پشتیبان دیتابیس و رسانه‌ها همراه چک‌سام.
- `scripts/run_migrations.py`: اجرای مایگریشن‌های ترتیبی و محافظت‌شده با چک‌سام.
- `scripts/release_health.ps1`: کنترل سلامت بک‌اند و فرانت‌اند.
- `scripts/check_deployment_release.py`: ممیزی آفلاین بستهٔ انتشار.

## پیش‌نیاز سرور

1. ویندوز، داکر دسکتاپ، گیت و تیل‌اسکیل نصب و روشن باشند.
2. پروژه در یک مسیر ثابت ویندوزی دریافت شود.
3. فایل `.env` به‌صورت دستی و امن ساخته شود.
4. حداقل ۳۰ گیگابایت فضای آزاد وجود داشته باشد.
5. رایانه وارد حالت خواب نشود و بازیابی پس از قطع برق فعال باشد.

## کنترل قبل از استقرار

```powershell
cd D:\project\kiaradbi
.\.venv\Scripts\python.exe scripts\check_deployment_release.py
docker compose config --quiet
```

## اجرای استقرار

برای بستهٔ آفلاین آماده، پایتون و گیت روی سرور لازم نیست؛ داکر و فایل‌های بسته کافی‌اند. ابتدا هر دو آرشیو را بارگذاری کنید:

```powershell
.\scripts\verify_release_package.ps1
docker load -i .\kiarad-images.tar
docker load -i .\postgres-image.tar
docker compose up -d --no-build --pull never postgres
.\scripts\restore_release_backup.ps1 -BackupDirectory .\backup
.\scripts\restore_release_media.ps1 -BackupDirectory .\backup
.\deploy.ps1 -SkipBuild
```

بازیابی فقط روی دیتابیس کاملاً خالی انجام می‌شود؛ روی دیتابیس دارای جدول متوقف می‌شود و هش پشتیبان را پیش از شروع کنترل می‌کند. رسانه‌های آرشیو نیز باید پیش از آزمون نهایی طبق ساختار پروژه در مسیرهای `private_uploads` و `kiarad-dashboard/public/uploads` قرار گیرند؛ این اسکریپت فقط دیتابیس را بازیابی می‌کند.

```powershell
.\deploy.ps1
```

این فرمان ابتدا تصاویر را می‌سازد، پستگرس را سالم می‌کند، پشتیبان می‌گیرد، مایگریشن‌ها را اجرا می‌کند، سرویس‌ها را بالا می‌آورد و سلامت را کنترل می‌کند.

در اولین استقرار آزمایشی می‌توان ساخت تصویر از قبل انجام‌شده را رد کرد:

```powershell
.\deploy.ps1 -SkipBuild
```

ردکردن پشتیبان فقط برای دیتابیس کاملاً خالی مجاز است:

```powershell
.\deploy.ps1 -SkipBackup
```

## پشتیبان دستی

```powershell
.\scripts\backup_release.ps1
```

خروجی در `private_exports/release-backups` ذخیره می‌شود و وارد گیت نمی‌شود.

## مایگریشن

```powershell
.\.venv\Scripts\python.exe scripts\run_migrations.py --status
.\.venv\Scripts\python.exe scripts\run_migrations.py --dry-run
.\.venv\Scripts\python.exe scripts\run_migrations.py
```

مایگریشن اعمال‌شده نباید ویرایش شود. تغییر جدید باید فایل شماره‌دار جدید داشته باشد.

## تیل‌اسکیل

پس از سالم‌شدن پنل روی سرور، سرویس تیل‌اسکیل به درگاه ۳۰۰۰ سرور منتقل می‌شود. سرویس لپ‌تاپ فقط بعد از تأیید دسترسی سرور بازنشانی شود تا قطعی ایجاد نشود.

## آزمون پس از استقرار

- ورود مدیر.
- ورود هر نقش پرسنلی و کنترل محدودیت دسترسی.
- بازشدن خزانه، پیش‌فاکتور، کاتالوگ، تارگت، نقشه و دستیار.
- کنترل پشتیبان و اجرای بازیابی روی دیتابیس موقت.
- کنترل اتصال خواندنی هلو و دیجی‌کالا.
- پایش لاگ و سلامت حداقل ۲۴ ساعت.

## وضعیت تصاویر آماده

در ۲ نوامبر هر دو ایمیج ساخته و در بستهٔ آفلاین ذخیره شدند. برای استفاده از این بسته نیازی به دانلود ایمیج از رجیستری نیست. تغییرات بعدی کد باید در ایمیج تازه بسته‌بندی و دوباره آزموده شوند.
