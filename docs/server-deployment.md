# راهنمای انتقال پنل به سرور ویندوز

## وضعیت فایل‌های استقرار

- فایل ترکیب داکر سه سرویس اصلی را آماده می‌کند: پُستگرس، واسط برنامه و پنل.
- درگاه پنل فقط روی `127.0.0.1:3000` باز می‌شود تا بعداً تیل‌اسکیل آن را به شبکهٔ خصوصی وصل کند.
- واسط برنامه در شبکهٔ داخلی داکر و روی `127.0.0.1:8000` میزبان در دسترس است؛ درگاه پایگاه‌داده هم فقط روی خود سرور باز است.
- پی‌جی‌ادمین اختیاری است و با نمایهٔ `tools` بالا می‌آید؛ برای آن باید رمز جداگانه در `.env` تنظیم شود.
- فایل `.dockerignore` مانع کپی‌شدن `.env`، نسخه‌های پشتیبان و بارگذاری‌های خصوصی داخل تصویرها می‌شود.

## پیش از راه‌اندازی

۱. داکر دسکتاپ و دبلیواس‌اِل ۲ را روی ویندوز سرور نصب و آماده کن.
۲. پروژه را روی سرور کپی کن و از روی `.env.example` یک `.env` بساز.
۳. برای `KIARAD_JWT_SECRET` و `POSTGRES_PASSWORD` رمزهای تصادفی و یکتا بگذار. از رمز پیش‌فرض استفاده نکن.
۴. در `.env` مقدار `DB_HOST` باید `postgres` باشد تا واسط برنامه در شبکهٔ داکر به پایگاه‌داده برسد.
۵. پیش از ورود کاربران، از پایگاه‌دادهٔ فعلی پشتیبان بگیر و آن را به سرور منتقل و بازیابی کن. حجم خالی داکر طرح‌واره و داده‌های واقعی پروژه را ندارد؛ برنامه خودش کل پایگاه را مهاجرت نمی‌دهد.
۶. نشانی وب‌سرویس هلو را فقط وقتی در دسترس بود تنظیم کن؛ بررسی سلامت پنل به هلو وابسته نیست.

## فرمان‌های راه‌اندازی

در پوشهٔ پروژه و پس از آماده‌شدن `.env`، ابتدا فقط پایگاه‌داده را بالا بیاور:

```powershell
docker compose config --quiet
docker compose up -d postgres
```

از پایگاه‌دادهٔ قبلی پشتیبان را بازیابی کن؛ بعد تصویرها را بساز و برنامه را اجرا کن:

```powershell
docker compose build
docker compose up -d
docker compose ps
```

نشانی داخلی پنل `http://127.0.0.1:3000/login` است. پس از بررسی سلامت، تیل‌اسکیل سرور باید همین نشانی محلی را به دامنهٔ خصوصی پنل وصل کند؛ درگاه ۳۰۰۰ را روی اینترنت عمومی باز نکن.

## پایداری داده و ابزار اختیاری

- برای خاموش‌کردن سرویس‌ها از `docker compose down` استفاده کن. فرمان `docker compose down -v` حجم پایگاه را حذف می‌کند؛ آن را اجرا نکن مگر اینکه حذف کامل داده‌ها قصدشده باشد.
- پی‌جی‌ادمین به‌طور پیش‌فرض اجرا نمی‌شود. برای استفاده، `PGADMIN_DEFAULT_PASSWORD` را با رمز یکتا در `.env` تنظیم و سپس با `docker compose --profile tools up -d pgadmin` اجرا کن. صفحهٔ آن فقط روی خود سرور باز است.
- این راهنما هنوز روی سرور مقصد ساخته و آزمایش نشده است؛ ساخت تصویرها به نصب داکر و دسترسی دریافت تصویرهای پایه و بسته‌های پایتون و نود نیاز دارد.

## تحویل ۸ نوامبر ۲۰۲۶

- نتیجهٔ آزمون همین سورس و موارد باقی‌مانده در `docs/Delivery_20261108.md` است؛ سند وضعیت جدید بر آمار تاریخی اولویت دارد.
- صفحهٔ ورود روی HTTP و HTTPS از مسیر هم‌مبدأ `/api/auth/login` استفاده می‌کند؛ مرورگر نباید به نام داخلی `backend` یا localhost رایانهٔ کاربر وصل شود. `KIARAD_API_URL` برای ارتباط سمت سرور/پراکسی است.
- بستهٔ تحویل سورس است و شامل دیتابیس واقعی، رسانه‌های خصوصی، اعتبارنامه‌ها و مدل صوت نیست. نسخهٔ کامل و امن این موارد جداگانه باید منتقل شود. ابزارهای `scripts/backup_release.ps1` و `scripts/restore_release_backup.ps1` و `scripts/restore_release_media.ps1` در پروژه وجود دارند؛ بازیابی باید ابتدا روی مقصد خالی آزمایشی بررسی شود.
- `migrations/0001_baseline.sql` فقط baseline است؛ آن را جایگزین ساخت اسکیمای کامل از backup نکنید.
